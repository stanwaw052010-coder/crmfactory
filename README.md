# crm.factory

**A modern operating system for your business.**

CRM для сервісного бізнесу: клієнти, записи, команда, продажі та аналітика —
в одній системі. Multi-tenant SaaS на Next.js 16, TypeScript, PostgreSQL і Prisma.

---

## Швидкий старт

```bash
npm install
cp .env.example .env      # заповніть DATABASE_URL і AUTH_SECRET
npm run setup             # міграції + demo-дані
npm run dev               # http://localhost:3001
```

`npm run setup` = `prisma generate` + `prisma migrate deploy` + `prisma db seed`.

### Якщо пароль загублено

Три шляхи, від звичайного до аварійного.

**1. «Забули пароль?» на сторінці входу** — працює для будь-якого акаунта.
Ви вводите email, система надсилає посилання, дійсне 60 хвилин і одноразове.
Після зміни пароля всі активні сесії цього користувача завершуються.

Щоб листи справді відправлялися, задайте `RESEND_API_KEY` (і бажано
`MAIL_FROM` зі своїм доменом). Без цього ключа лист не зникає — він
друкується в лог сервера (**Vercel → ваш проєкт → Logs**), звідки посилання
можна скопіювати вручну.

> Виведення в лог годиться лише для запуску. З реальними клієнтами ключ пошти
> обов'язковий: інакше кожен, хто бачить логи, може перехопити посилання.

Перевірити налаштування можна в `/admin` → картка **Пошта**: вона показує
поточного відправника і надсилає тестовий лист. Якщо Resend відмовив —
у відповіді буде причина (непідтверджений домен, обрізаний ключ,
обмеження пісочниці), а не «щось пішло не так».

Окремо про пісочницю: відправник `onboarding@resend.dev` доставляє листи
**лише на адресу власника акаунта Resend**. Щоб писати клієнтам, потрібно
підтвердити власний домен (Resend → Domains) і вказати його в `MAIL_FROM`.

**2. Аварійний доступ `/recovery`** — для власника платформи, коли пошта ще
не налаштована. Сторінка існує, лише якщо задані обидві змінні:

| Змінна | Значення |
|---|---|
| `SUPER_ADMIN_EMAIL` | email власника платформи |
| `ADMIN_RECOVERY_KEY` | довгий випадковий рядок, `openssl rand -base64 32` |

Ввівши email із `SUPER_ADMIN_EMAIL` разом із ключем, ви задаєте новий пароль.
Ключ звіряється порівнянням без витоку часу, спроби обмежені (5 на годину з
однієї адреси), кожна невдала пишеться в audit log. Змінити пароль можна
**тільки** акаунту з `SUPER_ADMIN_EMAIL` — правильний ключ із чужим email
не спрацює.

Захист тримається на тому, що змінні середовища бачить лише той, хто має
доступ до налаштувань хостингу. Якщо `ADMIN_RECOVERY_KEY` не заданий,
`/recovery` віддає редірект на `/login` — сторінки просто не існує.

**3. Прямо в БД** — якщо і це недоступно: видаліть користувача й
зареєструйтеся наново на той самий email. Роль супер-адміна звіряється зі
змінною `SUPER_ADMIN_EMAIL` при кожному вході, тож доступ до `/admin`
повернеться автоматично.

### Змінні середовища

Усі описані в [`.env.example`](./.env.example). Обов'язкові:

- `DATABASE_URL` — PostgreSQL 14+
- `AUTH_SECRET` — ≥32 символів, `openssl rand -base64 48`
- `NEXT_PUBLIC_APP_URL` — базовий URL для booking-посилань і QR

Опційні (архітектура готова, інтеграції — наступний етап): ключі провайдерів
нагадувань (Email / Telegram / SMS / WhatsApp) і Stripe.

Плюс: командне меню `⌘K` з глобальним пошуком, гарячі клавіші, сповіщення,
світла й темна теми, мобільна нижня навігація.

### Гарячі клавіші

Повний список — по `?` у самому застосунку. Основне:

| Клавіші | Дія |
|---|---|
| `g` потім `d` / `c` / `k` / `s` / `t` / `p` / `a` / `n` | Головна / Записи / Клієнти / Послуги / Команда / Воронка / Аналітика / Налаштування |
| `n` | Новий запис |
| `c` | Новий клієнт |
| `/` або `⌘K` | Пошук по всьому |
| `?` | Довідка по клавішах |

У полях вводу клавіші не перехоплюються, а недоступні за правами розділи не
показуються в довідці й не відкриваються.

### Автоматизації

**Налаштування → Автоматизації.** Правило «Коли → Якщо → Тоді»: подія в CRM,
набір умов, список дій. Наприклад — «візит завершено» + «візитів не менше
15» → «змінити статус на VIP».

| Коли | Якщо | Тоді |
|---|---|---|
| Створено запис | Кількість візитів клієнта | Створити сповіщення |
| Візит завершено | Послуга | Додати тег клієнту |
| Запис скасовано | Сума візиту | Змінити статус клієнта |
| Клієнт не прийшов | Статус клієнта | Створити заявку у воронці |
| Новий клієнт | Звідки запис (онлайн / CRM) | |

У текстах працюють підстановки: `{{клієнт}}`, `{{послуга}}`, `{{сума}}`,
`{{майстер}}`, `{{дата}}`.

Чотири рішення, які варто знати:

- **Один тригер, умови «всі разом», список дій — без гілок і циклів.**
  Візуальний конструктор із розгалуженнями виглядає солідно, але власниця
  салону не збирає в ньому графи. Складніше має сенс додавати тоді, коли
  по цих правилах стане видно, чого справді бракує.
- **Збій правила ніколи не ламає основну дію.** Автоматизації запускаються
  ПІСЛЯ того, як запис збережено: надбудова не має права коштувати
  користувачу втраченого запису.
- **Кожне спрацювання лишає слід** — включно з пропусками і причиною.
  Без журналу автоматизація виглядає як магія, про яку неможливо сказати,
  працює вона взагалі чи ні.
- **Умови й дії перевіряються схемою і на вході, і на виході з бази.**
  JSON міг покласти старіший код, і рушій не падає на правилі, форму
  якого більше не розуміє, — просто ігнорує незрозумілі рядки.

### factory AI

Асистент, який відповідає на питання про власний бізнес: «які послуги
принесли найбільше цього місяця», «кому пора нагадати про себе», «як
змінилася виручка».

Вмикається змінною `ANTHROPIC_API_KEY`; без неї кнопка пояснює, що
потрібно зробити. Доступ вимагає права `ai.use` — воно є в ролей, що
бачать аналітику, і **лише на тарифі PRO**. На нижчому тарифі панель
розповідає, що дає асистент, і веде до тарифів; співробітнику без доступу
до аналітики кнопки немає взагалі.

Як це влаштовано і чому саме так:

- **Модель не пише SQL.** Вона обирає інструмент (`get_revenue`,
  `get_top_services`, `get_lapsed_clients`, …) і параметри на кшталт «за
  скільки днів». `organizationId` підставляє сервер із сесії — у запиті
  просто немає місця, куди модель могла б підставити чужий id. Жодне
  формулювання питання не дістає чужі дані.
- **Числа рахує Postgres, не модель.** Інструменти повертають уже готові
  суми у валюті салону. LLM гарно формулює, але не має складати гроші —
  інакше у відповіді з'явиться правдоподібна, але вигадана сума.
- **Ліміт 30 запитів на годину на організацію** — не про навантаження,
  а про рахунок власника платформи.
- **Незмінна частина запиту кешується.** Опис інструментів і системна
  інструкція однакові в кожному зверненні; позначка стоїть у кінці
  `system`, а порядок складання запиту (tools → system → messages) робить
  так, що кеш накриває і те, і те. Виграш гарантований усередині одного
  питання: модель ходить по дані 2–4 рази поспіль. Префікс близько
  1000–1600 токенів при мінімумі 1024 — це межа, тому кожне питання пише
  в лог `кеш прочитано N`: якщо там стабільно нуль, кеш не працює.
- **Модель обирається змінною `ANTHROPIC_MODEL`.** За замовчуванням
  `claude-opus-5`, але для цієї задачі вона надлишкова: цифри рахує
  Postgres, а моделі лишається сформулювати відповідь. `claude-haiku-4-5`
  дешевша вп'ятеро і тут цілком справляється.
- Параметри від моделі обрізаються до розумних меж (період — до року,
  ліміти — до 25), а невідомий інструмент повертає помилку, а не падає.

### Фото салону та майстрів

П'ять знімків салону додаються під час онбордингу (крок «Про салон») або
згодом у **Налаштуваннях → Онлайн-запис**. Фото майстра — у картці
співробітника. Клієнт бачить і те, і те на сторінці запису.

Як це влаштовано:

- **Стиснення в браузері.** Фото з телефону важить 4–8 МБ; canvas зменшує
  його до 1600 px (аватар — до 512) і перекодовує в JPEG. Назад іде
  ~200 КБ. Власниці салону не треба нічого стискати вручну.
- **Байти лежать у Postgres** (`MediaAsset`), а не в зовнішньому сховищі.
  Нульова конфігурація важливіша за ідеальну архітектуру на цьому етапі:
  жодних ключів, бакетів і CORS. Перехід на Vercel Blob чи S3 зачепить
  лише `src/server/media.ts` — назовні віддається шлях `/api/media/<id>`.
- **Тип файла перевіряється за сигнатурою**, а не за заголовком від
  клієнта. SVG не приймається взагалі: це XML, тобто вектор для XSS на
  власному домені. Роздача йде з `X-Content-Type-Options: nosniff`.
- **Ліміт у 5 фото тримається на сервері** і переживає паралельні
  завантаження: після вставки кількість перераховується, і зайвий запис
  відкочується.

### Лояльність клієнтів

Рівень рахується із завершених візитів і живе поруч зі статусом, який ставлять
руками — розбіжність між ними видно одразу.

| Візитів | Рівень |
|---|---|
| 0 | Новий клієнт |
| 1 | Перший візит |
| 2–4 | Повертається |
| 5–14 | Постійний клієнт |
| 15+ | VIP |

Окремо в профілі — «останній візит понад 3 місяці тому»: найдешевший привід
повернути виручку.

## Тарифи, ліміти та оплата

| Тариф | Ціна | Співробітників | Що додається |
|---|---|---|---|
| Free | €0 | 1 | Календар, клієнти, онлайн-запис |
| Starter | €14/міс | 3 | Воронка, продажі, експорт клієнтів |
| Business | €29/міс | 10 | Аналітика, ролі та права доступу |
| Pro | €59/міс | без обмежень | Кілька філій, пріоритетна підтримка |

**Клієнтська база не обмежується на жодному тарифі.** Ліміт на клієнтів ламав би
онлайн-запис — нового клієнта створює сама форма бронювання, і бізнес не має
втрачати заявки через тариф.

Усі значення — у `src/lib/plans.ts`. Тариф звужує права ПІСЛЯ ролі й точкових
override-ів (`src/lib/auth/context.ts`), тому платну функцію неможливо відкрити
дозволом в обхід оплати. Ліміт співробітників рахує лише активних: деактивований
профіль зберігає історію записів і не займає оплачене місце.

### Онлайн-оплата (Stripe)

Без ключів застосунок повністю працює — просто кнопки оплати кажуть, що білінг
не підключено, а тариф видається вручну з `/admin`. Щоб увімкнути оплату:

1. У Stripe Dashboard створіть Product і три recurring-ціни в EUR
   (Starter €14, Business €29, Pro €59).
2. Додайте змінні: `STRIPE_SECRET_KEY`, `STRIPE_PRICE_STARTER`,
   `STRIPE_PRICE_BUSINESS`, `STRIPE_PRICE_PRO`.
3. Створіть вебхук на `https://ВАШ-ДОМЕН/api/webhooks/stripe` з подіями
   `checkout.session.completed` та `customer.subscription.*`.
4. Секрет підпису — у `STRIPE_WEBHOOK_SECRET`.

Оплата проходить на Checkout-сторінці Stripe, тож дані картки не потрапляють на
сервер застосунку. Зміна картки, рахунки й скасування — через Stripe Billing
Portal, кнопка «Картка й рахунки».

**Тариф змінює лише вебхук, і тільки після перевірки підпису.** Повернення
користувача на `success_url` нічого не підтверджує: вкладку можна закрити, а
платіж завершитися пізніше — тому стан підписки береться з події Stripe, а не
з переходу в браузері.

    admin/                # панель платформи (super admin)
    book/[slug]/          # публічний онлайн-запис
    onboarding/           # майстер налаштування workspace
  components/
    ui/                   # примітиви дизайн-системи
    layout/               # sidebar, topbar, ⌘K, мобільна навігація
    charts/               # графіки + перевірена палітра
    shared/               # логотип, статуси, метрики
  features/               # доменні екрани (calendar, clients, services…)
  server/

### Multi-tenant ізоляція

Кожна бізнес-сутність має `organizationId`. Доступ проходить через
`scoped()` / `assertTenant()` (`src/lib/db/tenant.ts`), тож помилка в запиті
дає порожній результат, а не витік чужих даних. Запис, знайдений за id,
перевіряється на приналежність організації перед будь-якою зміною.

### Права доступу

Матриця ролей (`OWNER` / `ADMIN` / `MANAGER` / `EMPLOYEE`) у
`src/lib/permissions.ts` плюс точкові override-и на рівні учасника.
Перевірка **завжди на сервері**:

- сторінки — `requireViewPermission()` (редірект на головну);
- серверні дії — `requirePermission()` (кидає, перетворюється на повідомлення).

Приховані кнопки на фронтенді — лише UX, не захист.

### Безпека

- Сесії в БД (миттєво відкликаються) + підписаний JWT у httpOnly-cookie
- `bcrypt` (12 раундів), однакова відповідь на «немає користувача» і «невірний пароль»
- Валідація Zod на межі кожної серверної дії
- Rate limiting: логін, реєстрація, відновлення пароля, бронювання, пошук
- Токени відновлення пароля зберігаються як SHA-256, згорають після
  використання (атомарний compare-and-set) і живуть 60 хвилин
- Форма «Забули пароль?» дає однакову відповідь для існуючого й неіснуючого
  email — її не можна використати як довідник зареєстрованих адрес
- Audit log усіх змін
- Слот онлайн-запису перераховується на сервері перед підтвердженням

### Рішення, які варто знати

- **Гроші — цілі числа в центах** (`Int`), жодної float-арифметики та проблем
  із серіалізацією `Decimal` у Server Components.
- **Час — UTC у БД**, робочі години — «хвилини від опівночі» (540 = 09:00).
- **Один рушій доступності** (`lib/availability.ts`) обслуговує і CRM,
  і публічний запис — неможлива ситуація «онлайн дозволив зайнятий час».
- **Палітра графіків перевірена** валідатором на смугу світлості, насиченість,
  розрізнюваність при дальтонізмі та контраст — окремо для світлої й темної тем.
- **Рух має пояснювати, а не прикрашати.** Картки з'являються каскадом по 40 мс
  (видно, що список зібрався), підкладка активного пункту меню їде між
  кнопками (видно, звідки й куди ви перейшли), показники докручуються від нуля
  (око встигає зауважити цифру). Тривалості — 150–350 мс, усе вимикається за
  `prefers-reduced-motion`.
- **Лічильник рахує в `useLayoutEffect`, а не `useEffect`.** Інакше браузер
  устигає намалювати кінцеве значення, і замість відліку виходить блимання.
  Початковий стан дорівнює кінцевому — щоб серверний HTML збігався з першим
  клієнтським рендером.

## Деплой

Потрібні дві речі: Node-хостинг і керована база PostgreSQL. Обидві —
з безкоштовним тарифом, якого вистачає для старту.

### Змінні середовища в продакшні

| Змінна | Значення |
|---|---|
| `DATABASE_URL` | рядок підключення від вашого Postgres-провайдера |
| `AUTH_SECRET` | `openssl rand -base64 48` — новий, не той, що локально |
| `NEXT_PUBLIC_APP_URL` | `https://ваш-домен` (без слеша в кінці) |
| `SUPER_ADMIN_EMAIL` | email, який отримає доступ до `/admin` |
| `ADMIN_RECOVERY_KEY` | ключ аварійного відновлення пароля (`/recovery`) |
| `RESEND_API_KEY` | ключ пошти — без нього листи йдуть у лог, а не адресату |
| `MAIL_FROM` | відправник, напр. `crm.factory <noreply@ваш-домен>` |
| `ANTHROPIC_API_KEY` | вмикає factory AI; без нього асистент вимкнений |
| `ANTHROPIC_MODEL` | опційно: дешевша модель для асистента, напр. `claude-haiku-4-5` |

`PORT` у продакшні задавати не потрібно — хостинг призначає порт сам.
На Vercel зайва змінна `PORT` у налаштуваннях лише заважає.

`NEXT_PUBLIC_APP_URL` вшивається у збірку — після зміни домену потрібен
повторний деплой.

### Vercel + керований Postgres (Neon / Supabase / Vercel Postgres)

1. Import Project → оберіть цей репозиторій.
2. Нічого в настройках змінювати не треба: команду збірки Vercel візьме
   з `vercel.json` (`npm run build:deploy` — генерація Prisma-клієнта,
   міграції, збірка).
3. Додайте змінні з таблиці вище.
4. Deploy.

Демо-дані в продакшні не потрібні: відкрийте свій домен, натисніть
«Спробувати безкоштовно» — і зареєструйте власний workspace через
звичайну форму. Якщо email збігається з `SUPER_ADMIN_EMAIL`, ви одразу
отримаєте доступ і до `/admin`.

Після першого деплою наповніть базу demo-даними (необов'язково):

```bash
DATABASE_URL="<продакшн-URL>" npm run db:seed
```

> Neon і Supabase працюють через пул з'єднань. Якщо провайдер дає два рядки —
> вкажіть pooled-URL у `DATABASE_URL`, а прямий додайте як `DIRECT_URL`
> і пропишіть його в `datasource` (`directUrl = env("DIRECT_URL")`):
> міграціям потрібне пряме з'єднання.

### Railway / Render (Postgres «в комплекті»)

1. New Project → Deploy from GitHub → цей репозиторій.
2. Додайте PostgreSQL — `DATABASE_URL` підставиться автоматично.
3. **Build:** `npm run build:deploy`, **Start:** `npm start`.
4. Допишіть решту змінних із таблиці.

`npm start` читає `PORT` із середовища, тому платформа сама вибере порт.

### Docker / власний сервер

```bash
npm ci
npm run build:deploy      # генерація клієнта + міграції + збірка
PORT=3000 npm start
```

Перед сервісом поставте reverse-proxy з HTTPS: session-cookie у продакшні
позначена `secure`, тож без TLS вхід не працюватиме.

### Після деплою перевірте

- вхід і реєстрація нового workspace;
- `/book/<slug>` відкривається й показує вільні слоти;
- створений онлайн-запис з'явився в календарі CRM;
- у Налаштуваннях → Онлайн-запис посилання веде на ваш домен, а не на localhost.

## Готово до наступного етапу

Архітектура закладена так, щоб додати без переписування:

- **Нагадування** — черга `ReminderJob` уже наповнюється; потрібна лише
  реалізація доставки для Email / Telegram / SMS / WhatsApp і воркер
  (`dispatchDueReminders()`).
- **Білінг** — модель `Subscription` містить `externalCustomerId`,
  `externalSubscriptionId` і період; лишається підключити Stripe Checkout і вебхуки.
- **Масштабування** — rate limiter має інтерфейс, сумісний із Redis;
  індекси для основних вибірок уже в схемі.
